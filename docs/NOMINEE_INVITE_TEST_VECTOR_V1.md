## Contract (confirmed against src/nominees/inviteToken.ts)

- `token = base64url(canonicalJson({ payload, signature }))`
- `signature = base64( raw P1363 r‖s, 64 bytes )` — NOT DER
- signed digest = ECDSA-P256 over `SHA-256(SHA-256(canonicalJson(payload)))`
  (WebCrypto `ECDSA{hash:"SHA-256"}` hashes once more on top of our SHA-256)
- `canonicalJson` sorts object keys recursively, no whitespace, no trailing newline

## Backend verify test

1. Load `creatorPubkeyPem`.
2. base64url-decode `inviteTokenString` → `{ payload, signature }`.
3. Recompute `SHA-256(SHA-256(canonicalJson(payload)))`.
4. ECDSA-P256 verify the raw-P1363 `signature` against that digest with the
   creator pubkey.
5. Assert: verify succeeds AND the decoded `payload` equals the §Payload above.

If verify fails, the divergence is in canonicalJson key ordering, the
double-hash, or DER-vs-P1363 — all pinned above.
